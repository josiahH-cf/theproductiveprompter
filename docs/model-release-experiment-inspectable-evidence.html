The Model Release Experiment: From Intuition to Inspectable Evidence

By Josiah Hunter•October 2, 2026•2 min read
  • One frozen creative-and-arithmetic challenge will be used across three models.
  • Settings, client behavior, and verification are recorded as separate layers.
  • Each later run is one anecdotal observation, not a universal model verdict.

I have a subjective feel for Claude and Codex. It is enough to motivate a closer look, not enough to count as evidence. What becomes visible when successive releases face the same inspectable task?

This article covers GPT-6.1 Sol, GPT-6 Sol, and GPT-6 Luna. OpenAI released GPT-6 Sol and GPT-6 Luna on September 22, 2026, describing both as reasoning models available through the Responses and Chat Completions APIs. It released GPT-6.1 Sol (gpt-6.1-sol) on September 29, 2026 for complex coding and professional work.

OpenAI documents all three as Work and Codex models, not Chat models. That documentation does not establish access for any particular experiment account. GPT-6.1 Sol is the newer Sol model, but that does not mean GPT-6 Sol was retired or replaced. These product facts can change, so they need a final check against the OpenAI changelog, model documentation, and rate card before publication.

The frozen task is PRINT-SHOP CHALLENGE v1.0, a 600–800-word original story paired with a checkable order-selection decision. An $80 initial materials limit becomes $66; machine time is capped at 120 minutes; a fixed $35 post-production expense follows production; and the repair goal is $220. A possible $100 donation remains unconfirmed. Each response must include a JSON receipt for the initial and revised plans, a checkable explanation, a feasible competitor, and a public update of no more than 80 words. The article will not reveal the worked optimum. The point is to make later responses comparable.

The user prompt stays byte-identical across trials, though native CLI system instructions may differ. One-factor profiles vary selected settings locally; factorial mode is a separate experiment. The three models share low through max reasoning effort, while GPT-6 Sol and GPT-6 Luna also support none. Native reasoning effort, native text verbosity, client configuration, diagnostic verbosity, and reasoning verification remain separate in the record. Diagnostic verbosity in Claude CLI is not model text verbosity.

This is a small field experiment: one original response per model/settings combination. The protocol preserves failures and unavailable-model outcomes, forbids silent substitution, and leaves original responses unpolished. Those are requirements for the trial design, not proof that completed trials followed it. That proof requires saved prompts, settings, manifests, and raw responses.

This article introduces the method. The controller later attaches readable model cards and linked run pages, while the updater handles missing trials and republishes the results section. Each saved run should be read as one model/settings observation, not a universal ranking.

Results update

121 original responses from 21 models are now saved. 83 receipts matched both optimal order plans, their totals, and the unconfirmed donation. 38 receipts failed at least one of those checks. 5 earlier failed attempts remain in the record.

13 models returned both passing and failing receipts across their saved profiles. Each profile has one response, so these differences do not establish that a setting caused a result. The receipt check does not assess story quality, story consistency, or word limits.

Each run shows the requested thinking and verbosity settings, the original response, the receipt checks, and the usage reported by the client.
